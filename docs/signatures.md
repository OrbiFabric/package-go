# Canonical subjects and signatures (S06)

Authority: frozen package-spec `7ff166365dc83cee783e4e6715225968c81ef7b9`, PKG-CONTRACT-009/010/011/012/021/022 and its machine schemas/crypto vectors. APIs remain provisional until the producer freeze; no V1 canonical/Merkle/proof/dual-sign protocol or migration is implemented.

`CanonicalJSON` independently encodes the restricted JSON domain: builtin safe integer types/json.Number, valid UTF-8 strings, booleans, nil, map[string]any and []any. It rejects floats, non-integer lexical forms, unsafe integers, unsupported Go/custom-marshaler representations and invalid UTF-8. Object keys sort by UTF-8 scalar-byte order; arrays retain order; string escaping follows exact PKG-CONTRACT-022 bytes, with direct slash/HTML/U+2028/U+2029/non-BMP output and no arbitrary NFC transformation. Nil typed maps/slices represent empty objects/arrays; untyped nil represents null. `ReadCanonicalJSON` first uses the strict duplicate/number/surrogate/BOM/trailing-value parser. Actual canonical byte, collection/depth/cycle/string/key-allocation budgets precede expansion; no canonical encoding delegates ordering/escapes to encoding/json or JCS.

`ContentCommitment` validates the full manifest JSON model, deduplicates file ContentIDs/sizes and hashes the ordered content set with its domain and LF. Empty trees commit `[]`; empty file bytes have their ordinary SHA-256 ContentID. Paths/ordinals/labels/representations are not ContentIDs. It does not read or certify object bytes.

`DeriveVersionSubject` validates/owns Package/Version/manifest and derives every subject field/digest. Full optional immutable fields, label and sealed metadata bind the subject; current mutable metadata, Working bytes, signatures/evidence, container bytes/hash and online state do not. Root parent is explicit null, child parent a scalar UUID. Caller-created optional data, shared expansion, depth/member/shadow/UTF-8 and aggregate immutable JSON budgets are checked before serialization. `DeriveSubjectAt` obtains actual lineage from the designated stable Root history. A caller-constructed `VersionSubject.Canonical` validates field shape but cannot certify claimed digests; verifiers always derive a fresh subject from actual immutable authority.

`ReadVersionSignature` validates closed fields, UUIDs/time, signer/algorithm constants, official/local conditional facts, canonical unpadded base64url with decode/re-encode equality and fingerprint over the raw 32-byte key. `SignatureSigningInput` canonicalizes the exact envelope without its signature under the Version signature domain. Its empty-signature placeholder is only an unsigned input preparation device, never mathematical verification. Key labels and attributed signed time/type/official facts are signed; changing them breaks the signature.

`VerifyEd25519Strict` adds independent canonical curve-point decoding (y<p, valid square-root recovery, no negative encoding of x=0), `[8]P != identity` for both A/R and `S<L` before the Go RFC8032 Ed25519 primitive checks the **uncofactored** equation. Public field arithmetic is variable-time and never handles production private keys. The supported Go minimum/current primitive computes `[S]B - [k]A` and compares canonical R directly; a cofactor-only acceptance is insufficient. Sources: [RFC8032 decoding/addition/verification](https://www.rfc-editor.org/rfc/rfc8032), [Go 1.23 minimum primitive](https://github.com/golang/go/blob/go1.23.0/src/crypto/ed25519/ed25519.go). Tests construct all eight torsion points and a signature for which only the cofactor equation holds; the latter has non-small-order A/R and canonical S but is rejected. RFC TEST 1, the frozen signature and 32 independent standard-library positive signatures pass. No permissive fallback, Ed25519ph/context mode or online check occurs.

`VerifyVersionSignature` derives authority from validated models. `VerifySignatures` reads actual history/control-path inventory, checks current format and frozen Version signing capabilities, signature/Package/Version/path IDs and recomputed subject digests, and reports every signature in path order. Callers hold one stable observation when coupling it to content/memory/evidence checks. A bad item keeps aggregate signature INVALID even beside a valid/trusted item; resource/cancellation/Host/trust errors propagate and make aggregate unperformed status NOT_CHECKED. Signer interpretation/cryptography is separate from committed content integrity and full completeness.

No signature files means ABSENT with UNKNOWN identity. Parsed signer claims remain UNTRUSTED even when their signature is invalid, as required by the frozen bad-signature fixture; malformed/uninterpretable attribution remains UNKNOWN. A mathematically valid signature is UNTRUSTED without a matching explicit Host rule, including embedded official self-claims. Only valid cryptography reaches `TrustPolicy.Trusted`, with Version signature purpose, raw public key and official facts; only Host authorization yields TRUSTED. Aggregate identity may reflect one actually trusted item while aggregate signature remains INVALID; per-item facts retain the distinction. Offline trust policies use local authorized pins/environment/profile rules, never automatic network lookup or signer self-assertion.

`CreateVersionSignature` accepts one SnapshotSource and one selected Signer with explicit key/type and, for official selection, environment/profile pins. It validates the request/key before Host effects, validates actual history/portable-memory IDs, requires signature capability declarations in format/Version, reserves all Package/Version/entry/memory/control IDs, derives the subject and holds one snapshot through profile/sign/verification. Stability is checked before profile/sign and after the response. Profile/key/type/env drift, signer error, invalid response, input mutation, cancellation, unstable source and snapshot close/begin errors return no success envelope, with no retries/fallback. Owned input/response/pin buffers prevent retained Host arguments from altering the SDK's expected facts. Official request/environment/profile fields follow the closed schema; they do not grant trust.

Signing returns a verified **proposal** only. It does not publish signature files, change Version/HEAD, export a container, require dual signing, certify full object coverage or prove current/third-party time. Object verification and formal-export policy remain separate explicit operations. Host Signer side effects may already have occurred if cancellation/stability/close later fails; no SDK success or automatic retry is claimed. Publication must retain exact selected facts, reject ID overwrite and remain isolated until the following codec/export gates pass. A production signer owns private keys/credential/keyring lookup; SDK portable models contain only public, Host-selected safe facts. Unit official-signing tests use an explicitly fake local TEST ONLY key/profile, not a real service or production identity.

Full Complete/evidence/coupled seven-level verification, native directory/ZIP publication, real Host signer/trust integration and product/external workflows remain later stages. These stage APIs do not certify an overall Package conformance level.
