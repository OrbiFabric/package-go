# ZIP v1 representation

`NewZIPSource` adapts a Host-owned `ArchiveSource` into `SnapshotSource`, the same logical tree interface used by Directory, history, signatures/evidence, scanning and publication. The Host selects an explicit artifact and supplies cancellable random access, immutable size, stability checks and owned close. The SDK performs no path discovery, automatic download or alternate-protocol fallback.

```go
source, err := packagego.NewZIPSource(authorizedArchiveSource, limits)
// Handle err, then use ReadHistory/Scan or staged Directory publication.
publication, err := packagego.PublishDirectory(ctx, source, directoryHost, limits, support)
```

The reader accepts a single display-directory wrapper or a direct Root with `.packtell/format.json`. Multiple candidate roots and extra top-level siblings beside a wrapper reject. All raw entry names are UTF-8; non-ASCII names require the UTF-8 flag. Unicode path extra fields never override names. The wrapper remains outside the logical Root, so its display name does not own the reserved `.packtell` control namespace. The stripped tree still enforces that namespace exactly. A safe archive without a Package discriminator returns NOT_PACKAGE, never a guessed Package authority.

An independent bounded parser reads EOCD/Zip64 directory facts before allocating entry collections. It validates disk counts, directory count/ranges, central records, flags, STORE/DEFLATE, regular-file/directory modes, implicit parents, duplicates, Unicode 16 NFC/full-fold collisions and portable paths before exposing streams. Local names/methods/flags/sizes/CRC must agree with central facts; correctly deferred data descriptors are supported with optional signatures and 32/64-bit sizes. Local extents cannot overlap or hide unaccounted prefix/gap/footer bytes. Unsupported encryption, multi-volume, patched data, compression methods, special files, reparse attributes and self-extracting prefixes reject. Ordinary record metadata/comments and bounded Zip64 end extensible bytes are not portable authority.

Expanded streams enforce actual size and CRC and require the compressed stream's exact extent. Buffered input implements `ReadByte`, so DEFLATE consumption is measured without treating prefetched trailing bytes as valid compressed data. Directory entries, including zero-byte DEFLATE directories, are expanded/CRC checked during preflight. File CRCs are checked when their streams are drained; opening a tree alone is not a claim that all payload has been verified. Staged Directory publication drains and validates every copied file before commit. Unsafe archive errors from committed object streams propagate as codec failures rather than being hidden as a missing object.

`Limits` bounds the artifact bytes, raw/implicit entry count, names/depth, each and total expanded bytes and compression ratio. For ZIP, `MaxTotalBytes` also bounds artifact input/output, including framing. Wrapper paths participate in these physical encoding limits. Ratio policy applies to readers and final writer compressed sizes. Actual expansion is stopped at declared size plus one diagnostic byte; a false advertised size cannot become an unbounded extraction.

`WriteZIP` validates one stable source through the shared Directory/history/object/memory/embedded-presence checks before any output. It writes only the selected single wrapper, independent file bytes and explicit empty directories using per-writer STORE/DEFLATE implementations. The Go standard writer handles framing and automatic Zip64; the reader does not delegate safety or entry allocation to the standard ZIP reader. Changing order, compression, mtime, permissions or wrapper affects container bytes without changing portable files or Version subjects.

`WriteZIP` writes only caller-isolated pending output, does not close/publish the caller's writer, and returns an empty result on source/write/frame-close/stability/close/cancellation/resource failures. It closes its own ZIP framing and observation. `ZIPWriteResult.ArtifactDigest` hashes container bytes and must never replace a logical Version subject. The Host must seal, read back and publish the artifact through its transaction contract; a pending write result is not a durable publication acknowledgement. Import/export workflow publication belongs to the separate planner stage. The Directory extraction path already uses `PublishDirectory` no-overwrite/isolation/recovery semantics.
