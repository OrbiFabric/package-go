# Portable memory (S05)

`ReadMetadata`, `ReadNotes`, `ReadTags`, `ReadProvenance` and `ReadEvent` apply the restricted JSON parser plus exact schema fields, constants, types, UUIDv7 and microsecond Gregorian UTC time constraints. Closed documents/records/targets/actors/relationships reject extra fields. Mutable metadata preserves open optional fields and namespaced extension objects; event data preserves arbitrary allowed JSON values. Unknown optional namespaced event types remain uninterpreted explanations, not executable state transitions. Required interpretation belongs in declared required capabilities, which Root/history readers check before reading these facts.

Notes sort by (note_id, revision), begin at 1 and remain contiguous with a fixed target. `Notes.Current()` returns the latest revision including tombstones: deleted requires an empty body, and a later revision may restore the same identity. Tags form one contiguous global sequence, use nonempty NFC case-sensitive values without surrounding Unicode whitespace, and reject duplicate adds/removal of absent values. `Tags.Current()` returns sorted active values. Projection methods are for validated models; caller-constructed input goes through the write planner/readers before use.

`ReadEvents` accepts zero bytes or one LF-terminated event per line, rejecting empty lines, physical CR, leading BOM, incomplete final lines, duplicate event IDs and strict JSON/schema errors. Escaped CR and U+FEFF inside legitimate strings remain ordinary values. Line budget includes LF; JSON byte/depth/collection limits still apply. A fixed small read buffer feeds bounded line growth; aggregate JSON/NDJSON, single file and event count policies stop expansion. File order survives equal/reversed times; no chronology sorting or state replay occurs. Interruption/cancellation discards partial results.

`ReadPortableMemory` obtains actual linear history from the supplied stable Host view. It checks all document PackageIDs, typed targets against all historical entities, event references against the complete event inventory, and provenance content targets against historical manifest ContentIDs. Previously deleted files/folders remain valid targets. Package targets must equal the PackageID. Provenance IDs sort uniquely; source kinds come from vocabulary, names/timestamps follow schema; relationships reference another Package and optional Version, without opening it or creating a branch. The combined identity inventory rejects cross-domain reuse and respects policy; IDs from validated signature/evidence/delivery control paths are also reserved without claiming those envelopes verified. Ordinary payload/extension filenames do not create protocol identities. Missing optional Core files get empty defaults and are listed in `MissingPaths`; absence is retained for later Complete verification, never concealed by materialized defaults.

Portable memory is independent of committed reconstruction. Current title/notes/tags/events/provenance changes do not rewrite Version sealed metadata, manifests, committed objects or HEAD. Events never substitute for manifests, historical objects, a database or a network dependency. Commit validates actual portable memory inside its existing transaction and reserves note/event/provenance IDs, including tombstoned notes, before generating new entity/Version IDs.

`PlanPortableMemoryUpdate` reads existing history/memory, validates caller JSON before serialization and re-reads SDK-generated documents through the same schema/relationship checks. Existing note revisions are immutable even when a new note inserts in sorted order; tags/events/provenance retain their immutable prefix. Metadata may change known display facts. Unknown optional metadata facts, including nested fields, survive unless `MemoryWriteIntent.AllowOptionalFactRemoval` represents explicit user removal intent. The planner rejects a lossy write otherwise. Revision collections receive a byte/domain/depth check one record at a time before expanded array/map allocation; shared values and cycles cannot cause unbounded encoder growth. Whole prospective tree and aggregate JSON/NDJSON budgets are checked before Host approval.

`PortableFactPolicy.ApprovePortableFacts` is a mandatory Host boundary for these write plans. The Host selects privacy-safe domain facts using an explicit allowlist: credentials/private keys/keyring locators, signed/fetch URLs, absolute local paths, SQLite IDs, caches/indexes/embeddings/worker state and telemetry are not portable facts. Schema validation is not redaction and cannot prove opaque strings safe. The policy gets an owned copy of exact proposed document bytes; it cannot mutate accepted plan output. Policy rejection propagates without fallback. A standalone plan neither writes nor publishes anything: the caller retains one stable authorized source observation and publishes all changes atomically in isolated output. Native production publication/authorization/restart behavior belongs to the following codec/Host stages.

`PortableMemoryPlan.Extensions` inventories bytes the representation writer must retain in addition to its five new memory documents. `CopyExtensions` preflights the designated Root, streams declared extension files verbatim to an isolated `PayloadWriter`, preserves empty directories, enforces size/cancellation and retains I/O/close errors. Even extension files named `.json` remain opaque, never Core schemas or executable code. Unknown optional namespaces can be preserved without understanding them; unsupported required capabilities fail closed. The Host writer creates required parent directories safely. On error the entire pending output is discarded. Copying bytes does not certify them as privacy-approved; representation export still requires its own Host selection policy. Directory/ZIP round trips and end-to-end publication are not certified by this isolated copy helper.
