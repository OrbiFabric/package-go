# Directory representation and publication

`PublishDirectory` copies one caller-selected Package tree, including dirty payload, empty directories and opaque optional extensions. User files remain directly under Root, alongside `.packtell`. Raw control JSON and signature/evidence files are retained byte for byte. Container paths and filesystem metadata do not create identities or change Version subjects.

```go
limits := packagego.DefaultLimits()
source, err := packagego.NewDirectorySource(authorizedAbsoluteRoot, limits)
// Handle err, then select a distinct Host-authorized destination.
host, err := packagego.NewDirectoryHost(authorizedAbsoluteDestination, limits)
// Handle err, then supply the capabilities this application implements.
publication, err := packagego.PublishDirectory(ctx, source, host, limits, support)
```

The SDK owns the whole-tree path/control preflight, actual HEAD parent chain, all historical manifests and references, all referenced and extra object hashes/sizes, portable memory semantics and declared embedded evidence presence. Complete trees require their portable files. Missing objects cannot be replaced by Working Tree bytes or a network resolver. Known-invalid signatures/evidence reject before output begins; original bytes remain unchanged and their verification dimensions stay independent. Valid but untrusted mathematics can be copied without granting identity trust. A returned publication is a durable output acknowledgement, not a FULL verification result or conformance-level certification. Use the independent verification APIs for their documented dimensions; the coupled verifier and seven-level test matrix are documented in [S11 conformance](s11-conformance.md).

The SDK holds one source observation through copying, seals pending output, reads it back through the same validators and compares every copied raw file digest and tree entry. It checks source stability and closes every observation before publication. HEAD is the last file written inside isolated pending output. Source/read/write/close/resource/cancellation/validation/Host failures return an empty `DirectoryPublication` and an error. No partial output is returned as successful.

Hosts can implement `DirectoryHost` and `DirectoryTransaction` for their own filesystem/platform. The contract requires pending output outside both source and target, exclusive ownership until publication, independent regular-file writes, no-overwrite publication, durability acknowledgement and pending-only abort. A platform without an atomic operation must isolate pending output and recover it or explicitly report unfinished publication. Host locks and recovery records never belong inside `.packtell`. In-place Version commits continue to use the separate `CommitHost` expected-HEAD/stable-payload/HEAD-last transaction contract; a Directory export does not change source HEAD or implement a Version commit.

The supplied Linux reader anchors Root and every parent with directory descriptors and `O_NOFOLLOW`; it never performs an unsafe path-based `Lstat`/`Open` pair. It refuses links and special entries, bounds enumeration, checks descriptor metadata and rehashes fully read files on stable checks. Metadata is a change detector, not portable content authority. Host authorization and exclusion of hostile concurrent writers are still required; stronger snapshot/locking facilities can be supplied through `SnapshotSource`. Input hard links are read as bytes; output and historical restoration create independent files.

The Linux publisher creates a random private `0700` sibling directory, uses exclusive `0600` files, flushes files and directories, retains the sealed observation's stamps/digests for a final read-back, then calls `renameat2(RENAME_NOREPLACE)`. Existing files, directories (even empty ones) and links remain untouched. Unsupported syscall/filesystem behavior fails without replacement-rename fallback. The destination parent is anchored and checked again before publication. Linux amd64 behavior is tested; arm64/riscv64/loong64 syscall numbers are from Linux UAPI, with other Linux publication architectures explicitly unsupported. The API compiles on other OSes, whose built-in native operations explicitly return `ErrDirectoryPlatformUnsupported`; those Hosts must provide native isolation themselves.

If the move may have happened but acknowledgement fails, `ErrPublicationUncertain` requires Host inspection/recovery. The SDK returns no success artifact and never removes the destination. Abort verifies that the held tree is still named pending before deleting its children, including when a move occurred without a successful reply. Ordinary handled failures clean up owned pending output. A process interruption can leave an isolated sibling pending directory; it does not expose the destination. Host startup recovery must treat such pending directories as unfinished, never as completed Packages. Physical power-loss/storage-controller guarantees and production recovery integration are not inferred from process-exit tests.

Authority: frozen [package-spec contracts](https://github.com/OrbiFabric/package-spec/blob/7ff166365dc83cee783e4e6715225968c81ef7b9/specification/zh-CN/10-implementation-contracts.md), clauses 002/016/017/018/019. Linux native semantics are documented by [open(2)](https://man7.org/linux/man-pages/man2/open.2.html) and [rename(2)](https://man7.org/linux/man-pages/man2/rename.2.html); syscall identifiers follow the Linux UAPI `asm/unistd_64.h` and `asm-generic/unistd.h`. Native implementations use only the Go standard library.
