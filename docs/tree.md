# Root, path, HEAD and Working Tree contract (S03)

Authority remains frozen `7ff166365dc83cee783e4e6715225968c81ef7b9`, contracts 002/003/004/008/016. Public APIs remain provisional. No alternate/V1 layout, fallback, old-data migration, network or product/DB dependency exists.

PreflightTree examines all supplied paths, kinds and implicit parents before payload I/O. It rejects traversal/absolute/drive/UNC/backslash paths, duplicate/file-directory conflicts, links/junctions/special nodes, nonportable components, reserved Windows basenames, trailing dots/spaces, C0/DEL and names exceeding 255 UTF-16 units. Whole-tree NFC collisions precede Unicode16 full-fold collisions and individual name rejection. Root control namespace aliases are reserved; a nested .packtell remains ordinary payload. Returned paths are sorted and have no trailing slash. Counts include implicit directories; budgets include supplied control/object/payload bytes. Host policy separately limits path bytes and tree depth, without changing normative component limits.

PathCollisionKey implements Unicode 16 NFC(Default Full Case Folding(NFC(name))), using C/F mappings and excluding Turkic T. Pinned generation inputs, source hashes, Unicode license, official normalization and folding data are retained. All 19,965 normalization rows, all 1,557 C/F fold rows and unchanged unlisted scalars pass. Current Go Unicode tables never determine normalization/collision behavior. Materialization never silently renames collisions.

ReadRoot examines only the caller-designated Root. After computing whole-tree safety, it may read only the exact known-safe format discriminator to label recognition on a rejected input; it never opens unsafe or payload paths on that route. Required capability/profile rejection occurs before history/payload. The exact control allowlist includes Core files/directories, complete Version directories, correctly named objects/signatures/deliveries/evidence and one-to-one declared extension namespaces, including empty declared namespaces. Unknown control paths fail. It validates Package identity, exact HEAD encoding, unborn history emptiness and HEAD document/path/Package IDs. Full linear history, committed objects, portable memory, crypto and evidence verification are separate later-stage operations; RootInspection does not claim those dimensions.

HEAD accepts exactly ASCII unborn+LF or lowercase UUIDv7+LF, without BOM/CRLF/whitespace/aliases. ReadHEAD checks bytes; Version existence is checked by ReadRoot. WithExpectedHEAD checks the current HEAD inside explicit Host isolation before running callback effects; stale/cancelled inputs do not run a commit callback. Isolation/close failures remain errors. Host lock/journal state stays outside the portable tree; DB projections are never substituted for HEAD. Durable Version/object writes and HEAD-last publication are the next commit stage.

Manifest.Paths derives paths solely from parent/name facts, preserving FileID/FolderID. Iterative topology walks and path/depth limits bound adversarial trees. Authority names validate exact Unicode16 NFC, Root control exclusion, component safety and sibling full-fold collisions.

Scan uses an explicit SnapshotSource/TreeSnapshot Host port. The Host must provide one authorized stable Root generation, enforce no-follow regular-file I/O and detect concurrent changes, or report an error from CheckStable. Streams and observation calls must honor cancellation. The SDK preflights paths/control topology, bounds/hashes raw payload streams and discards all proposal entries/changes on I/O, size, stability or close failure, returning UNREADABLE. Host metadata/inodes may detect unstable reads but never enter logical identity or equality. No implicit filesystem or network source is acquired. Production authorization/no-follow/snapshot adapter validation remains a Host/codec concern; test adapters are not production adapters.

A same-path/kind entry can retain its HEAD ID. A Host tracking map may prove rename/move or provide new working IDs; it must not duplicate IDs, change historical kinds or reference absent paths. Equal bytes alone never prove continuity. Missing continuity yields Added/Removed with unknown new IDs. Diff reports ID-matched path and content changes separately, including explicit empty folders, and requires complete working entries including parent directories. Folder and filesystem directory vocabulary are mapped correctly. Permissions, mtime, owner and inode are absent from equality. New scanned/proposed identities do not enter committed history until a future commit.

DIRTY does not change HEAD, committed object bytes or historical validity. UNBORN remains its own state. Scan makes no assertion about full history/Complete/signature/identity/evidence/online dimensions and creates no Version. Native filesystem test evidence covers actual local edits, mtime independence, detected mid-scan mutation and symlink rejection on the validation host. Host-reported junction/special kinds are rejected by the SDK; native Windows junction and other-platform runtime checks are NOT_RUN here.
