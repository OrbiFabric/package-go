# Delivery and independent evidence (S07)

Authority: frozen package-spec `7ff166365dc83cee783e4e6715225968c81ef7b9`, PKG-CONTRACT-015/018/020/021 and delivery/evidence/four subject schemas. APIs remain provisional; no V1 identity/Merkle/dual-sign behavior or migration.

`ReadDelivery` validates closed fields, UUIDv7/time, explicit reference arrays, sorted unique nonempty signature IDs and append-ordered unique evidence IDs/kinds/embedded flags. Recipient/purpose/channel are optional public, Host-selected facts, not database/runtime serialization. `DeliveryDigest` is H(J(delivery without evidence_refs)); it retains all identity/creation/recipient/purpose/channel/signature facts. `AppendEvidenceRefs` owns a validated proposal and retains the old prefix. `ValidateDeliveryAppend` rejects prior reference removal/reorder/edit or any change to receipt-bound facts. Reference count/byte guards precede expanded model allocation. These pure helpers do not authorize publication or substitute for actual reference verification.

`CreateDelivery` obtains one Host snapshot, actual lineage and portable-memory/control ID inventory, verifies the selected Version/format delivery-evidence capability and every selected existing signature for that Version, derives its actual subject, generates a fresh reserved ID and owns caller-selected optional facts. No valid selected signature can hide another selected absent/wrong/invalid signature. An explicit PortableFactPolicy approves an owned copy of exact proposed bytes; rejection, instability, cancellation and begin/close errors return no descriptor success. This method publishes nothing, signs nothing, and does not change Version/HEAD or contact Providers. Following codec/export operations must preflight the whole prospective output and enforce atomic no-overwrite publication. Formal Delivery requires valid mathematical signatures; identity trust remains a separate Host fact.

`EvidenceSubject` is the closed union of cloud anchor, Package witness, delivery receipt and lifecycle witness subjects. Kind maps underscores to hyphens in its exact subject schema/domain. Common facts bind EvidenceID, Package/Version/actual VersionSubject digest, issuer and creation/observation times. Receipt alone adds actual DeliveryID/delivery_digest/outcome; lifecycle alone adds actual event_id/H(J(full event)). Inappropriate variant facts reject. `EvidenceSubjectDigest` hashes subject.schema + LF + canonical subject; `EvidenceSigningInput` hashes no data implicitly and returns envelope domain + LF + J(envelope without signature). `ReadEvidenceEnvelope` applies exact closed schema, key/base64/fingerprint checks; the shared strict Ed25519 verifier validates mathematical signatures. No Cloud API response schema replaces these portable models.

`VerifyEvidence` reads actual stable Root history, portable event inventory, signatures, Deliveries and all supplied evidence objects offline. It validates Delivery path/Package/Version/digest and every signature reference, actual evidence path and kind/subject mapping, actual immutable Version digest, receipt-bound Delivery facts and lifecycle event digest. All supplied objects are checked even if not referenced by a Delivery. It keeps per-Delivery/per-evidence facts, retains invalid items, and does not modify committed object integrity. Wrong signatures/references/subjects/receipts/events produce invalid evidence facts, never a convenient alternative match or replay-derived Version.

A reference with embedded=true must have its object path: absent files appear in `MissingEmbedded`, an explicit negative coverage fact for the later full completeness verifier. A present invalid envelope is an independent evidence failure. External references appear in `External` and never imply a Resolver/network access; if their bytes are actually supplied, those objects are still verified. No supplied attestation objects means ABSENT; all checked valid objects mean VALID; invalid Delivery/evidence facts mean INVALID; interruption/resource/Host/trust failure makes the aggregate NOT_CHECKED. A delivery descriptor may remain otherwise verified while its absent embedded bytes are separately missing; neither descriptor validity nor positive inventory alone certifies FULL. Full profile verification must combine paths/memory/objects/embedded coverage and retain independent signature/evidence dimensions.

Evidence issuer trust uses a distinct per-kind subject-schema purpose in `TrustRequest`, raw public key and explicit issuer/key labels. It carries no Version signer official self-claims; a key authorized for Version signing is not automatically an issuer key. Valid math defaults to UNTRUSTED; only an explicit Host purpose/key/issuer pin yields TRUSTED. Wrong-purpose Host rules cannot be silently reused. Public issuer/time claims do not independently prove current service status or third-party time. `ValidateEvidenceUnchanged` rejects rewriting any old envelope/subject; a new issuer observation gets a new EvidenceID, while append uses the existing inventory API.

Offline results always have online=NOT_REQUESTED. `QueryEvidenceOnline` is a separate explicit transient Host port over EvidenceID/kind, accepting CURRENT/REVOKED/UNAVAILABLE and propagating interruption/Host failure as unavailable. It owns service authorization/credentials and does not infer fetch URLs from IDs. Its response cannot become an edit to historical portable bytes, subjects, signatures or digests; revoked current status does not change an old mathematically valid snapshot. No SDK network client, polling worker, credential lookup or implicit status request is added.

Native publication, Directory/ZIP round trips, real issuer/Provider/official signer integration, full seven-level/profile verification and product acceptance are following stages. Tests here use published TEST ONLY keys/fixtures; they do not claim real service issuance, production identity or global freshness.
