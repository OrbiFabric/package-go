# Offline verification

`Verify(ctx, source, limits, VerificationOptions)` owns one explicitly selected snapshot, reads its safe discriminator and required capabilities, checks schema/topology/history/memory references, then objects/signatures/evidence and Working Tree. Borrowed scans use the same observation. It does not discover other Roots, execute payloads, fetch objects or online status, select signers, hydrate input or publish output. Hosts supply safe cancellable I/O and optional purpose-bound trust policy.

`Verification.Result` reports recognition, structure, working state, committed integrity, history completeness, signature, identity, evidence and online separately. Content, signature and evidence component reports retain individual observations. Content coverage alone does not certify history completeness. Reason codes are deduplicated; an operation error accompanies protocol rejection or an incomplete Host/policy observation. Callers inspect both the error and independent dimensions. There is no aggregate validity boolean.

Complete input always executes the coupled proof: unique HEAD chain covers every Version; schema/paths/references/capabilities are legal; all distinct historical objects and extras have correct SHA-256/size; required portable memory is present and valid; declared embedded evidence exists. Only actual offline bytes can yield FULL. Missing objects/memory/embedded obligations yield NOT_FULL; bad objects/topology/schema/memory yield INVALID. Bad signature mathematics and bad evidence remain independent. DIRTY Working Tree does not rewrite committed facts. Empty UNBORN history can be FULL.

Core input defaults to history completeness NOT_CHECKED; `ProveCompleteness` explicitly requests the coupled proof. `CompleteSupport()` describes SDK semantics, without claiming a conformance level. Unsupported required capabilities reject before history; unsupported optional signature/evidence/memory semantics are not interpreted or claimed checked. If unsupported optional semantics prevent completeness proof, it stays NOT_CHECKED. Embedded public keys never create trust; valid mathematics with no authorized pin is UNTRUSTED.

Stability, owning-snapshot close or cancellation failure revokes successful proof observations. Host trust failure remains an unchecked signature observation, never ABSENT or trusted. Resource limits stop before diagnostic discriminator expansion; limits are Host policy, not topology corruption. A safely rejected ZIP may retain a single exact, bounded, locally framed and CRC-checked format marker for independent recognition, while exposing no rejected tree or unsafe entry stream. Ambiguous/malformed/unstable markers do not create recognition.
