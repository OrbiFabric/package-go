# Linear history, objects, restoration and commits (S04)

Frozen authority: `7ff166365dc83cee783e4e6715225968c81ef7b9`, contracts 004/006/007/010/018/020/021. APIs remain provisional. Signatures, container representations, product DBs and network services are not prerequisites for a committed Version.

ReadHistory reads every committed Version directory and validates documents/path/Package identity, current required-capability coverage, manifest topology, historical entry-kind continuity, and a unique actual HEAD-to-parent-to-null chain. Root ordinal is one, each child increments its single parent, and the chain must cover every Version directory once. Missing parents, cycles, detached/multiple roots and parent arrays fail. Returned records follow actual parent authority oldest first, never UUID/filename/ordinal sorting. All historical ContentID/size pairs form one sorted deduplicated union, including HEAD. Aggregate control JSON and historical entity-count budgets bound retained data. Sources must provide a stable authorized Root observation when these operations are coupled.

VerifyCommittedContent derives history from the supplied Root and reads all referenced object paths, plus extra objects, verifying raw SHA-256 and size. It cannot call ContentResolver or borrow Working Tree bytes. Referenced missing/unreadable objects yield committed integrity UNAVAILABLE; wrong referenced bytes/size yield INVALID. Extra corrupt objects block completeness but do not misstate otherwise correct referenced committed integrity. Missing object coverage implies NOT_FULL; invalid objects imply INVALID. Valid objects alone leave history_completeness NOT_CHECKED: required portable memory and declared embedded evidence remain independent later-stage checks. This operation is not a full Complete-profile verifier.

PlanMaterializeVersion and MaterializeVersionPayload derive one historical tree from its manifest and object store, retaining empty bytes/folders. They write independent verified streams only into caller-isolated pending output. They do not move HEAD, publish a container, require old signing keys, read Working Tree bytes, fetch content or modify databases. Any error requires discarding pending output; successful payload restoration is separate from whole-profile/container publication.

Commit owns all protocol facts and serialization. CommitHost/CommitTransaction provide explicit authorization, stable source reads, pending object/Version storage, reader/writer isolation, durable publication and crash recovery. One outer transaction covers expected HEAD comparison, valid prior history/object coverage, stable Working Tree scan, ID allocation, model validation, whole prospective tree/resource preflight, verified durable object streams, two durable new Version documents, final stability/expected HEAD recheck and HEAD-last publication. Borrowed scan views cannot close/release outer isolation. Objects are reused by hash, and previously committed documents are never rewritten. No signer or ZIP is selected implicitly.

New entries use fresh UUIDv7; tracked continuity preserves old identities, content changes retain FileID, and copies without continuity get new IDs. All historical Package/Version/entry IDs and control-path evidence/signature/Delivery IDs are reserved; additional non-entry portable-memory IDs can be supplied through ReservedIDs and must be automatically integrated when memory semantics are implemented. Historic entry extras and current manifest extras are preserved, with new manifest facts merged. New sealed metadata is an explicit snapshot. Caller-created optional facts reject malformed UTF-8, floats, out-of-domain numbers, cyclic/deep/member/encoded-byte expansion before serialization. NextOrdinal stops at the exact maximum without wrapping.

Pending proposals stay outside committed history. StageVersion may not overwrite an existing Version. Host PublishHEAD installs complete durable staged data under isolation, publishes HEAD last, and keeps crash/interruption states unavailable or explicitly incomplete. The SDK reads back HEAD acknowledgement before returning success. Abort can remove only pending output; it must never remove published or prior history even on uncertain publication errors. Close/publication/cancellation errors return no success artifact, and the caller reads authoritative state before resolving/retrying. Abort cleanup uses a bounded cancellation-independent context so a cancelled operation can still isolate/discard pending output.

Unit transaction Hosts persist actual SDK JSON/object bytes and verify sequencing, concurrent stale writers and failure behavior; they are not production native filesystem/authorization/journal adapters. Those adapters and real restart/crash behavior remain required in later codec/Host/product stages. S04 does not certify portable memory, crypto/evidence, seven-level conformance or product E2E. Root format/profile labels alone never establish FULL.
